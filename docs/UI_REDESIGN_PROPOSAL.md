# EncoreHub 前端界面更新设计书

> 目标：在现有 React + Tailwind 暗色界面基础上,提升**友好度、美观度、简洁度**
> 范围：仅设计建议,不含代码。基于当前真实 UI 现状提出
> 设计原则:克制留白、层次清晰、状态可感知、无障碍可达

---

## 一、现状概览(设计起点)

当前界面已具备完整骨架,值得肯定:

- 单屏桌面布局:左侧栏(可折叠 w-64/w-12)+ 右侧聊天区 + 全局设置弹窗
- 暗色为默认,亮/暗/跟随系统三态主题,Inter + JetBrains Mono 字体
- 消息气泡、流式光标、slash 命令菜单、供应商切换、四个设置面板齐全
- 空状态较完整(无对话/无消息/空列表)

**主要短板**(本设计书要解决的):

1. 状态/错误色硬编码(`green-400`/`red-500`),不随主题适配
2. 聊天区无标题栏,看不到当前对话名/模型上下文
3. 无障碍缺失:图标按钮仅靠 `title`、弹窗无焦点陷阱、slash 菜单无 ARIA 角色
4. 交互粗糙:删除用原生 `window.confirm`、重命名仅双击可发现、加载只有裸 spinner
5. 无响应式处理,固定像素宽度

---

## 二、设计语言(统一基调)

**视觉气质**:安静、专业、不抢戏。内容(对话)是主角,UI 是舞台。

- **留白优先**:消息区左右留出舒适边距(桌面宽屏时内容最大宽度约 720–760px 居中),避免一行文字横跨整屏导致阅读疲劳
- **层次靠对比而非线条**:用 `surface` / `surface-alt` 的微妙明度差分区,少用硬边框,边框降为 1px 低对比
- **圆角统一**:卡片/气泡/输入框统一一套圆角阶梯(如 8/12/16),不混用
- **动效克制**:仅在状态切换、出现/消失、hover 用 120–200ms 缓动,拒绝弹跳和炫技
- **图标统一**:沿用 lucide,统一线宽与尺寸(16/20),图标必配可访问标签

## 三、配色系统升级(P0,低成本高收益)

**问题**:状态色硬编码,亮色主题下 `green-400`/`red-500/10` 对比失衡。

**方案**:把语义色纳入 CSS 变量 token 体系,与现有 `surface/accent` 并列:

| Token | 用途 | 亮色 | 暗色 |
|-------|------|------|------|
| `success` | 在线/成功 | `#2f9e44` | `#51cf66` |
| `warning` | 接近上限/警示 | `#e8590c` | `#ffa94d` |
| `danger` | 错误/删除 | `#e03131` | `#ff6b6b` |
| `info` | 系统消息 | `#1971c2` | `#74c0fc` |

每个语义色再派生 `-bg`(10% 透明填充)与 `-border`,供 toast、状态 pill、错误横幅统一调用。**收益**:全部状态视觉随主题自动适配,告别 ad-hoc 配色。

代码块背景 `#1e1e1e` 同样收进 token(`code-bg`),亮色主题下改用浅色高亮主题。

## 四、布局级改进

### 4.1 聊天区顶部栏(新增)

当前聊天区无 header,用户看不到「我在跟谁说话」。建议加一条轻量顶部栏:

```
┌─────────────────────────────────────────────┐
│  对话标题(可点击重命名)      ◯ 模型 ·  ⋯ 更多 │
└─────────────────────────────────────────────┘
```

- 左:当前对话标题,点击即行内重命名(替代「双击列表项」的隐藏交互)
- 中/右:当前 provider·model 小徽章(点击快速切换,联动设置)
- 右:更多菜单(导出对话、清空、删除)
- 视觉:贴顶、半透明毛玻璃背景、滚动时投下极淡阴影暗示层级

### 4.2 内容宽度约束

消息区设最大内容宽度并居中,两侧自适应留白。宽屏不再「满屏拉通」,阅读节奏更舒适。

### 4.3 响应式与窄窗

- 窗口宽度 < 768px 时侧栏自动折叠为图标态/抽屉
- 设置弹窗在窄窗下转为全屏 sheet,避免 640px 固定高度溢出

## 五、组件级改进

### 5.1 消息气泡(MessageBubble)

- **助手消息**:保持无填充的「文档式」排版(已是亮点),但增加 hover 时浮现的操作条:复制、重新生成、引用
- **用户消息**:accent 填充气泡保留,稍降饱和度避免在长对话里过于跳眼
- **代码块**:复制按钮常驻右上(当前 hover 才现,触屏/无鼠标场景不可达),加语言标签
- **时间戳/token**:以极淡 muted 小字置于气泡下方,默认弱化,hover 增强

### 5.2 输入框(InputBox)

- 字数计数从「数字」改为**进度环**,接近 8000 上限时染成 `warning` 色,更直观
- slash 命令入口加一个 `/` 提示芯片,首次使用者更易发现
- 发送/停止按钮过渡用形变而非硬切换,流式中按钮明确呈 `Stop` 态

### 5.3 Slash 命令菜单

- 命令项加图标 + 分组(如「对话」「知识」「系统」)
- 补 ARIA:`role="listbox"` + `aria-activedescendant`,键盘高亮项滚动入视

### 5.4 对话列表

- 删除改用**行内确认或轻量弹窗**替代原生 `window.confirm`(后者破坏视觉一致性)
- 重命名入口显式化:hover 显示编辑图标,不只靠双击
- 按时间分组(今天/昨天/更早),长列表更易扫读
- 当前项高亮用左侧 accent 竖条 + 微填充,而非整行重色

### 5.5 设置弹窗

- 加焦点陷阱(Tab 不逸出弹窗)+ Esc 关闭 + 打开时聚焦首个可交互元素
- 左侧 tab rail 选中态用 accent 竖条 + 图标染色
- API Key 输入统一:show/hide 眼睛图标、已设置显示 `•••• 已配置` 而非明文长度

## 六、状态与反馈

- **加载**:列表/面板加载用**骨架屏**替代裸 spinner,减少跳动感
- **流式**:保留闪烁光标(亮点),首 token 前的「Thinking…」可加渐显的占位骨架
- **错误**:统一一套 toast 组件(用 `danger` token),全局右下角堆叠,可手动关闭 + 自动消失;替代当前各面板各写一套红色横幅
- **空状态**:每个空状态配一句引导文案 + 一个主操作按钮(如空对话列表 →「开始新对话」),而非仅一张静态卡片
- **成功反馈**:复制、保存 key、引用入聊天等给一次性轻 toast 确认

## 七、无障碍(A11y)清单

当前缺口集中,逐项补齐成本低、收益高:

- [ ] 所有图标按钮补 `aria-label`(不止 `title`)
- [ ] 设置弹窗:焦点陷阱 + 返回触发元素 + `aria-modal`
- [ ] slash 菜单:`role="listbox"` / `option` + `aria-activedescendant`
- [ ] 状态 pill 不仅靠颜色传达(加图标/文字),照顾色盲
- [ ] 焦点可见环(focus-visible)统一用 accent,键盘导航全程可见
- [ ] 对比度:文字/背景满足 WCAG AA(注:完整合规需配合辅助技术实测与专家评审)

---

## 八、落地优先级

| 优先级 | 项目 | 理由 |
|--------|------|------|
| **P0** | 语义色 token 化、A11y 标签、删除/确认替换原生弹窗 | 成本低,体验与一致性立竿见影 |
| **P1** | 聊天区顶部栏、内容宽度约束、统一 toast | 提升「懂上下文」的友好感 |
| **P2** | 骨架屏、消息操作条、对话列表分组 | 精致度打磨 |
| **P3** | 响应式/窄窗、设置全屏 sheet | 覆盖更多使用场景 |

---

## 九、不做什么(避免过度设计)

- 不引入重型 UI 框架,继续用 Tailwind + lucide,保持轻量
- 不做花哨动效与渐变,克制是这款工具型产品的气质
- 不改变核心信息架构(侧栏 + 聊天 + 设置弹窗),只打磨不重构
