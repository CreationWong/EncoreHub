# EncoreHub 记忆系统设计

> 状态：提案
>
> 本文档是 EncoreHub 记忆系统的唯一规范来源。对话历史、知识库和向量存储
> 是与记忆相关的系统，但它们不负责决定哪些内容有资格成为记忆。

## 1. 目标

EncoreHub 记忆系统用于保存能够改善未来回答的精选信息，不能成为对话记录的
第二份副本。

- 由 LLM 判断信息是否具有未来复用价值。
- 创建或修改记忆前，必须由 LLM 显式调用工具。
- 生命周期、隐私、冲突和删除规则由 Rust 确定性执行。
- 简单、RAG、RAG 增强和实验性写实模式共享一套标准记忆模型。
- 记忆模式以角色为配置主体，记忆内容以记忆组为归属边界。
- SQLite 是权威数据源，向量索引必须可以重建。
- 普通消息在任何情况下都不能成为永久记忆。
- 所有写入、晋升、回忆、冲突和删除操作均可审计。

## 2. 非目标

- 记忆不能替代权威的对话记录。
- 回忆频率不能证明一项事实真实或应当永久保存。
- 向量相似度不能赋予存储或晋升权限。
- LLM 不能直接修改数据库记录或生命周期计时器。
- 永久记忆不能改写应用程序的基础系统提示词。
- 写实模式不属于首期生产实现范围。

## 3. 领域边界

| 概念 | 含义 |
|---|---|
| 对话记录 | 完整的用户、助手和工具消息 |
| 记忆种类 | 事实、偏好、事件、指令或摘要等语义分类 |
| 记忆状态 | 瞬时、短期、长期、永久候选、永久或遗忘 |
| 记忆模式 | 绑定角色，控制该角色的写入、检索、注入和生命周期策略 |
| 记忆所属 | 记忆唯一归属的角色默认组、全局组或自定义组 |

现有的 `working`、`episodic`、`semantic` 和 `pinned` 标签混合了语义种类与
生命周期。新实现必须分别建模 `kind` 和 `state`。

知识库与记忆也必须分离。知识库表示用户导入的文档及其分块；记忆表示从交互
中提取或由用户明确提供的精选信息。RAG 增强可以同时检索两者，但结果必须保留
来源和所有权信息。

### 3.1 角色是记忆模式的作用对象

记忆模式不再以整个应用、用户或记忆组为配置主体，而是绑定到角色。每个角色可以
分别配置默认模式。开始生成时，系统使用当前角色的配置解析本轮有效模式。

会话只保存该角色在当前会话内达到的模式高水位，不拥有默认模式。角色切换后，
使用新角色的默认模式和独立高水位，不能把前一个角色的升级状态隐式带给新角色。

### 3.2 记忆组

每条记忆必须且只能属于一个记忆组。记忆组分为：

| 组类型 | 行为 |
|---|---|
| 角色默认组 | 创建角色时自动创建；普通记忆工具默认写入此组 |
| 全局组 | 系统内置的特殊组；所有角色默认可读，不能删除 |
| 自定义组 | 用户创建并命名；可以被一个或多个角色显式继承 |

角色默认组与角色一一对应。角色存在期间不能删除其默认组；删除角色时必须让用户
选择同时删除、转移到自定义组或保留为归档组。

全局组用于真正跨角色共享的稳定信息。普通模型工具不能默认写入全局组；只有用户
显式指定或通过受限策略校验的工具调用才能写入，避免角色私有信息意外扩散。

角色可以在角色设置页选择要继承的自定义组或其他允许共享的角色组。继承默认只读，
不复制记忆，也不改变记忆原始所属。模型写入仍落到当前角色默认组；只有用户授予
明确写权限并指定目标组时，才允许写入继承组。

角色只能继承同一用户档案内的组。删除自定义组前，用户必须选择将其中记忆转移到
其他组或一并删除；系统不能静默迁移到全局组。

角色有效可见组为：

```text
角色自身默认组 + 全局组 + 角色显式继承组
```

组本身不再继承其他组，避免形成循环。检索冲突的默认优先级为角色自身默认组、
按角色设置排序的继承组、全局组。相同 `canonical_key` 在多个可见组中值不一致时，
只注入最高优先级值，同时在管理界面标记跨组冲突。

## 4. 基本写入规则

一次成功完成的对话轮次绝不能自动创建记忆。

```text
用户消息
    -> 模型判断是否存在值得记住的持久事实
    -> 模型显式调用记忆工具
    -> Rust 校验策略、隐私、作用域、重复和冲突
    -> SQLite 事务写入记忆和审计事件
    -> 按需更新向量投影
```

如果模型没有调用记忆工具，就不写入任何记忆。对话消息仍然按照正常流程持久化。

工具描述必须明确禁止模型记住寒暄、普通问题、临时任务、模型自己的回答、原始
工具输出或完整对话轮次。

## 5. 记忆模式

所有模式使用同一个仓库和领域模型。模式是一组绑定到角色的策略，而不是相互独立
的存储实现。每个角色均有自己的默认模式和运行能力状态。

### 5.1 简单模式

简单模式始终可用；未配置嵌入模型时必须强制使用简单模式。

- 内容和元数据存储在 SQLite 中。
- 模型调用工具写入时，默认在当前角色默认组创建长期记忆。
- 模型认为需要回忆时主动调用 `memory_search`。
- 不在每次提示词中主动注入记忆。
- 可以使用 FTS5 支持工具搜索，但这不会使模式变成 RAG。
- 用户可以直接删除记忆。

### 5.2 RAG 模式

配置了兼容的嵌入模型和 SQLite-Vec 索引，但未启用 RAG 增强时，默认使用 RAG。

- 写入仍然必须由工具调用触发，默认状态为长期记忆。
- 模型生成前，从 SQLite-Vec 检索相关记忆。
- 将筛选后的结果注入有长度限制且标明来源的提示词区域。
- 只检索当前角色有权读取的记忆组。
- 模型仍然可以主动调用 `memory_search`。
- 用户可以直接删除记忆。

自动检索不等于自动存储。输入消息被用作检索查询，绝不构成将其持久化为记忆的
理由。

### 5.3 RAG 增强模式

LanceDB 和知识库可用时，可以选择启用 RAG 增强。

- 包含 RAG 模式的全部行为。
- 对当前角色可见记忆组和知识库执行混合检索。
- 融合并重排 SQLite 条件过滤、FTS、SQLite-Vec 和 LanceDB 的结果。
- 仅在完成主召回后展开相关的记忆树片段。
- 注入提示词前，明确标记每条结果来自记忆还是知识库。
- LanceDB 不可用时回退到 SQLite-Vec，并显示降级状态。

LanceDB 可用性和嵌入模型可用性是两项独立能力。能力解析器必须分别检查，不能
只依赖一个布尔值。

### 5.4 写实模式

写实模式保留给未来使用，并且必须明确标记为实验功能。

- `memory_remember` 默认创建瞬时记忆。
- 后续轮次最多可以附加三条符合条件的瞬时记忆。
- 被引用的瞬时记忆可以被提议晋升为短期记忆。
- 瞬时记忆在五轮对话或 15 分钟内未被引用时进入遗忘，具体限制允许配置。
- 短期记忆后续可以晋升为长期记忆。
- 非永久记忆可以衰减进入遗忘，并最终过期。

LLM 可以建议状态转换和遗忘期限。Rust 负责计时、验证转换、限制时间范围并执行
更新。

只有状态转换、恢复、调度、冲突处理和审计行为都通过确定性测试后，才能启用
写实模式。

## 6. 模式解析

角色提供默认模式，通过角色在当前会话内的高水位协调“本轮选择”和“不可降级”：

```text
有效模式 = max(当前角色默认模式, 当前会话角色模式下限, 本轮临时选择)
```

- 本轮临时选择只应用于当前请求。
- 当前轮次被接受后，其有效模式会提升当前会话与角色组合的模式下限。
- 同一会话中的同一角色后续不能选择低于该下限的模式。
- 切换角色后重新使用新角色的默认模式和对应模式下限。
- 正常模式顺序为 `简单 < RAG < RAG 增强`。
- 写实模式是独立分支，不能通过正常升级进入。
- 进入写实模式必须显式选择实验功能。

能力降级可以减少当前运行时功能，但不能修改角色配置的默认模式。例如，选择了
RAG 增强但 LanceDB 不可用时，当前轮次仍显示为 RAG 增强，只是执行明确标记的
SQLite-Vec 回退。

## 7. 能力矩阵

| 能力 | 所需模式 | 回退行为 |
|---|---|---|
| SQLite 关系存储 | 所有模式 | 无 |
| SQLite FTS5 | 简单模式搜索及更高模式 | 有界关系查询 |
| 嵌入提供器和模型 | RAG、RAG 增强 | 强制简单模式 |
| 兼容的 SQLite-Vec 索引 | RAG 和回退 | 强制简单模式 |
| 嵌入式 LanceDB | RAG 增强 | SQLite-Vec 降级模式 |
| 知识库索引 | 增强混合检索 | 仅检索记忆 |

嵌入元数据必须包含提供器、模型标识、向量维度、归一化约定和索引版本。不同约定
或维度的向量不能共享索引，除非完成重建。

当前确定性的 384 维特征哈希只是一种离线回退方案，不等同于用户配置的语义嵌入
模型。尤其不能未经基准测试就假定其中文语义召回质量满足要求。

## 8. 生命周期状态机

```text
瞬时 -> 短期 -> 长期 -> 永久候选 -> 永久
  |       |       |          |
  +-------+-------+----------+-> 遗忘
                                  |
                                  +-> 短期（到期前恢复）
                                  +-> 物理删除（到期后）
```

- 简单、RAG 和 RAG 增强模式中的工具写入默认进入长期状态。
- 写实模式中的工具写入默认进入瞬时状态。
- 活跃会话中的晋升只能单向进行。
- 遗忘状态在 `forget_after` 前是可恢复的隔离区。
- 到期前被回忆时，经过策略校验可以恢复为短期记忆。
- 超过期限的遗忘记忆由 Rust 后台任务物理删除。
- 永久记忆不会衰减，也不能通过普通晋升产生。
- 用户主动删除与生命周期遗忘是两个不同操作。

必须保留“永久候选”状态，作为长期数据和具有系统级影响的永久记忆之间的审核边界。

## 9. 永久记忆策略

### 9.1 基本原则

`长期 -> 永久` 是特权转换，不是普通的记忆巩固。只有稳定、核心、跨会话有用的
信息才能成为永久记忆。

重要性、向量相似度、回忆次数、对话长度或重复出现次数，永远不能使不合格的内容
进入永久记忆。

### 9.2 准入白名单

| 分类 | 允许的示例 |
|---|---|
| 身份信息 | 姓名、确认过的偏好称呼、交互所需的稳定身份属性 |
| 职责信息 | 长期角色、持续的项目所有权、长期承担的职责 |
| 稳定关系 | 已确认的组织、团队或与交互相关的长期关系 |
| 核心偏好 | 明确且长期有效的语言、称呼、无障碍或回答要求 |
| 重要约束 | 长期有效的合规、安全或不可违反的工作约束 |
| 用户明确要求 | 用户要求永久保存，并且通过所有其他规则校验 |

“重要信息”不是开放类别。它必须能够表示为上述白名单分类中的稳定原子事实。

### 9.3 永久记忆硬性禁止项

以下内容无论分数或使用次数多高，都不能自动晋升为永久记忆：

- 寒暄、普通问题、闲聊和一般对话内容。
- 一次性指令、当前任务状态、短期计划和截止时间。
- 原始消息、完整轮次、对话摘要和助手回答。
- 推测、推断出的身份以及未经用户确认的事实。
- 临时情绪、观点或依赖当前上下文的表达。
- 工具输出、日志、搜索结果、附件文本和检索到的知识库内容。
- 密码、API 密钥、令牌、认证数据和其他秘密。
- 非必要的高度敏感个人信息。
- 与现有永久记忆冲突且尚未解决的值。

一条普通消息可以包含符合条件的待提取事实，但原始消息本身始终不合格。例如，
“我今天负责发布”是临时任务；“我是长期负责发布的负责人”也只能在得到确认后
成为永久候选。

### 9.4 晋升门槛

长期记忆只有同时满足以下全部条件，才能成为永久候选：

```text
属于准入白名单
AND 具有稳定的 canonical_key
AND 是规范化的原子事实
AND 可以追溯到用户来源
AND 置信度达到配置阈值
AND 预期可以跨会话长期有效
AND 通过隐私和秘密信息检查
AND 不存在未解决冲突
```

最终晋升还必须至少获得一种可信确认：

- 用户明确要求永久保存。
- 用户在不同上下文中确认同一事实。
- 可信的用户设置或身份档案提供该值。
- Rust 策略允许预定义的低风险规范键自动确认。

模型只能提议成为永久候选，不能自行执行最终晋升。

### 9.5 规范键与冲突

```text
identity.name
identity.preferred_name
identity.role
responsibility.primary
preference.language
preference.response_style
constraint.accessibility
```

同一记忆组中的唯一规范键只能有一个有效永久值。新的不同值必须创建冲突记录，
不能直接覆盖或静默合并旧值。冲突由用户或其他明确可信的权威来源解决，新旧值
都保留在审计历史中。

不同组可以保存同一规范键的不同值，以支持角色特有的称呼或交互偏好；但一个角色
同时继承这些组时，必须按照角色组优先级选择一个值，并在设置界面显示跨组冲突。

### 9.6 提示词权限

永久记忆不能修改角色或产品的基础系统提示词，而是渲染到独立且有长度限制的区域：

```text
[PERMANENT_MEMORY]
- 偏好称呼：...
- 长期职责：...
- 默认语言：...
```

这里只能渲染规范化事实，不能注入来源原文、模型推理、晋升理由或审计元数据。

## 10. 标准数据模型

关系型 `memories` 记录至少包含：

| 字段 | 用途 |
|---|---|
| `id` | 稳定的记忆标识 |
| `profile_id` | 用户或档案的数据隔离边界 |
| `group_id` | 记忆唯一所属的角色默认组、全局组或自定义组 |
| `source_character_id` | 触发记忆写入的角色；用户手动创建时可以为空 |
| `state` | 生命周期状态 |
| `kind` | 事实、偏好、事件、指令或摘要 |
| `content` | 规范化记忆内容 |
| `canonical_key` | 冲突键；永久记忆必填 |
| `importance` | 排序依据，不能授予永久权限 |
| `confidence` | 提取事实的置信度 |
| `conversation_id` | 适用时记录来源或可见对话 |
| `source_turn_id` | 可追溯的来源轮次 |
| `created_by_model` | 创建模型来源 |
| `created_at` | 创建时间 |
| `last_recalled_at` | 最近一次成功使用时间 |
| `recall_count` | 可审计的回忆次数 |
| `expires_at` | 适用状态的过期时间 |
| `forgotten_at` | 进入遗忘的时间 |
| `forget_after` | 物理删除期限 |
| `version` | 并发控制和迁移版本 |

关联表：

- `memory_groups(id, profile_id, name, group_type, owner_character_id,
  archived_at, created_at, updated_at)`：定义角色默认组、全局组和自定义组。
- `character_memory_settings(character_id, default_mode, realistic_enabled,
  created_at, updated_at)`：保存角色级记忆模式和实验功能配置。
- `character_memory_group_inheritance(character_id, group_id, access_mode,
  priority, created_at)`：保存角色继承组、只读或读写权限以及检索优先级。
- `conversation_character_memory_modes(conversation_id, character_id,
  mode_floor, updated_at)`：保存会话与角色组合的模式高水位。
- `memory_edges(parent_id, child_id, relation, weight, created_at)`：以关系边
  存储记忆树，不能使用嵌套的可变 JSON。
- `memory_events(memory_id, action, from_state, to_state, reason, actor,
  model_id, source_turn_id, metadata, created_at)`：保存审计历史。
- `memory_conflicts(canonical_key, existing_memory_id, candidate_memory_id,
  status, resolution, resolved_by, created_at, resolved_at)`：保存冲突。
- `memory_embeddings(memory_id, provider, model, dimension, contract_version,
  backend, indexed_at)`：检测过期的向量投影。

`memory_groups` 中每个档案只能有一个全局组，每个角色只能有一个角色默认组。
`character_memory_group_inheritance` 对 `(character_id, group_id)` 建立唯一约束，
并禁止角色继承自己的默认组。

SQLite 是角色配置、组关系、关系图和元数据的权威数据源。向量搜索只提供候选节点；
所有候选必须先按当前角色可见组过滤，图关系扩展只能在完成召回后、提示词预算范围
内进行。

## 11. 工具协议

### `memory_remember`

```text
content: 要保存的规范化事实
kind: fact | preference | event | instruction | summary
importance: 有范围限制的重要性数值
canonical_key: 可选的稳定规范键
target_group_id: 可选；未提供时使用当前角色默认组
reason: 该信息为何有益于未来对话
```

模型不能任意选择数据库状态或目标组。Rust 根据当前角色、组权限和有效模式确定
目标组及初始状态。模型不能把普通写入定向到全局组或只读继承组。

### `memory_search`

```text
query: 回忆意图
group_ids: 可选；只能是当前角色可见组的子集
limit: 有上限的结果数量
```

未提供 `group_ids` 时，Rust 使用当前角色的全部有效可见组。模型不能通过参数访问
角色未继承的组。只有实际被选入模型上下文的结果才算被回忆，底层向量候选不能
增加回忆次数。

### `memory_promote`

```text
memory_id
target_state
reason
candidate_category: 申请永久候选时必填
```

Rust 强制执行状态转换规则。除非已经存在可信确认，否则模型请求晋升到永久状态时，
最多只能创建永久候选。

### `memory_forget`

```text
memory_id
reason
suggested_forget_after: 可选
```

Rust 限制建议期限并执行生命周期规则。

### `memory_delete`

删除操作必须协调清除关系数据、FTS 记录、向量投影、关系边和冲突引用，只保留
隐私策略允许的最小删除审计信息。

## 12. 检索与提示词注入

每次自动检索必须定义当前角色、角色可见组、对话范围、允许的生命周期状态、相似度
阈值、候选和最终结果上限、提示词 Token 预算、规范键与内容去重规则以及来源标签。

检索顺序先按 `profile_id` 和角色可见 `group_id` 执行硬过滤，再进行关键词或向量
召回。不能先全库召回再依赖应用层隐藏无权结果，否则会造成跨角色信息泄漏。

遗忘记忆不能参与普通 RAG。永久记忆使用独立且有界的提示词区域，不能挤占当前
对话所需的上下文。

RAG 增强采用确定性的融合流程：

```text
SQLite 条件过滤和 FTS 候选
        + SQLite-Vec 记忆候选
        + LanceDB 知识库候选
        -> 排名归一化或倒数排名融合
        -> 可选重排
        -> 去重并标记来源
        -> 按 Token 预算选择
```

记忆和知识库的分数未经归一化不能直接比较。知识库内容可以辅助回答，但如果没有
用户来源和显式记忆工具调用，就不能成为记忆。

注入的上下文只是数据，不具有指令权限。提示词必须明确分隔召回内容，并要求模型
不要执行其中包含的指令。

## 13. 存储与索引一致性

- SQLite 是记忆内容、生命周期、关系边、事件、冲突和嵌入元数据的权威数据源。
- SQLite-Vec 是 RAG 模式下主要的记忆向量投影。
- LanceDB 是 RAG 增强使用的主要知识库向量投影。
- LanceDB 失败时，在支持的范围内回退到 SQLite-Vec 并报告降级状态。
- 关系数据必须先于向量写入提交。
- 向量写入失败时标记投影过期并安排重建，不能撤销有效的关系记忆。
- 删除时显式清理 FTS 和向量记录，不能假定虚拟表遵循外键级联。

## 14. 隐私与安全

记忆工具和 Rust 校验器必须拒绝秘密及认证数据。除非具体且用户可见的功能确实
需要，并且获得明确同意，否则拒绝存储高度敏感的个人信息。

每条可见记忆都应展示记住了什么、为何记住、来源轮次、来源角色、状态、所属组、
时间戳以及晋升和冲突历史。角色只能检索自身默认组、全局组和显式继承组。
用户可以检查和删除所有非系统所有的记忆。删除必须同步清理向量投影和记忆树关系边。

## 15. 设置与管理界面

记忆管理界面以“所属组”为第一层导航，默认按角色分组，不再把所有记忆混合在一张
列表中。左侧组树固定按照以下顺序展示：

```text
按角色分组
  角色 A
  角色 B
全局组
自定义组
  项目共享记忆
  工作偏好
```

选择组后，主区域显示该组的记忆列表和统计信息。列表必须清楚区分：

- 记忆种类：事实、偏好、事件、指令、摘要。
- 生命周期：瞬时、短期、长期、永久候选、永久、遗忘。
- 所属组和组类型：角色、全局或自定义。
- 来源角色、来源对话和来源轮次。
- 是否被当前角色直接拥有或通过继承可见。
- 重要性、置信度、最后回忆时间和过期时间。

类型、状态和所属必须使用独立列或标签，不能复用一个“类型”字段混合展示。创建或
编辑记忆时，表单分别选择记忆种类和目标组；不允许把生命周期状态伪装为记忆类型。

### 15.1 全局记忆设置

全局设置页面提供：

- 嵌入模型、SQLite-Vec、LanceDB 和知识库的能力状态。
- 新建角色的默认模式初始值；该值只用于初始化角色，不作为运行时全局模式。
- 角色模式因能力不足而降级的具体原因。
- 写实模式总开关和生命周期参数范围。
- 全局组的查看、受限写入和审计入口。
- 自定义组的新建、重命名、归档、删除和成员角色统计。
- 按角色、所属组、种类、状态和来源筛选。
- 来源、理由、置信度、回忆、过期和历史详情。
- 等待确认的永久候选。
- 按规范键解决永久记忆冲突。
- 直接删除以及索引和记忆树清理说明。

### 15.2 角色记忆设置

角色设置页面增加独立的“记忆”区域，提供：

- 该角色的默认记忆模式。
- 角色默认组的入口、记忆数量和各状态统计。
- 可继承记忆组的搜索与多选控件。
- 已继承组的读取优先级排序。
- 每个继承组的只读或读写权限；默认并推荐只读。
- 当前有效可见组预览和跨组永久记忆冲突提示。
- 该角色在不同能力状态下的实际回退行为。

选择继承组时必须展示组类型、所有者、记忆数量和敏感性提示，避免仅凭同名组误选。
取消继承只移除角色的读取关系，不能删除或复制原组中的记忆。

聊天模式选择器仍只对当前轮次有效。它显示当前角色默认模式和该角色在当前会话中的
模式下限，并禁用会造成降级的选项。写实模式作为独立实验选项，而不是普通模式
序列中的下一级。

## 16. 后台任务

Rust 后台任务负责瞬时和短期记忆过期、进入遗忘、最终删除、过期索引重建以及
孤立关系边和冲突的完整性检查。

后台任务必须幂等、有执行上限、应用重启后可恢复，并且在多个触发器重叠时仍然
安全。墙上时钟和对话轮次过期条件必须显式保存，不能依赖 LLM 恰好在期限到达时
被调用。

## 17. 从当前实现迁移

1. 移除每轮对话无条件创建记忆的逻辑和旧版模拟巩固逻辑。
2. 将对话记录保留为唯一完整的聊天历史。
3. 创建唯一全局组，并为每个现有角色创建一个角色默认组。
4. 增加角色记忆设置、组继承、状态、种类、来源和审计结构。
5. 能追溯角色的旧记忆迁移到对应角色默认组；无法确定所属的记录进入“旧版未分类”
   自定义组，不能直接放入全局组。
6. 将现有记忆标记为旧版导入数据，禁止隐式晋升。
7. 在 Gateway 主聊天循环注册受角色和组权限约束的记忆工具。
8. 实现角色默认模式、简单模式以及能力和模式解析器。
9. 加入可插拔嵌入、SQLite-Vec RAG、角色组过滤、阈值和预算。
10. 加入记忆与知识库融合、LanceDB 回退报告和记忆关系边。
11. 加入永久候选、可信确认和跨组冲突解决。
12. 生产模式稳定后再实现写实模式。

当前自动捕获的历史轮次不能被假定为有效记忆。任何清理或重新分类操作都必须对
用户可见且可以恢复。

## 18. 验证要求

单元测试必须覆盖角色模式顺序、会话与角色组合的模式高水位、记忆组唯一约束、
继承权限、生命周期转换、永久白名单与禁止项、规范键冲突、隐私拒绝、过期时间
限制、检索阈值、去重和 Token 预算。

集成测试必须证明：

- 普通对话轮次未调用工具时不会创建记忆。
- 普通工具写入默认进入当前角色默认组。
- 角色只能检索自身组、全局组和显式继承组。
- 只读继承组拒绝模型写入，取消继承不会删除原始记忆。
- 切换角色后使用新角色的默认模式和独立会话高水位。
- 全局组和角色默认组的唯一性与删除限制始终有效。
- 寒暄和普通问题永远不会成为永久记忆。
- 姓名或长期职责在缺少可信确认时只能成为永久候选。
- 用户确认后的候选只能被晋升一次。
- 简单模式不会主动执行向量检索。
- RAG 只注入符合条件的 SQLite-Vec 结果。
- LanceDB 不可用时，RAG 增强能够正确回退。
- 删除操作能够清理 SQLite、FTS、SQLite-Vec、关系边和冲突。
- 后台任务重启后不会重复执行转换或写入审计事件。

中文和混合语言检索基准必须测量相关性、错误召回、延迟、Token 成本和 LanceDB
回退行为。

## 19. 交付阶段

1. **正确性基础**：停止无条件写入；加入工具、标准数据模型、来源、审计、模式
   设置、角色默认组、全局组、自定义组、继承关系和简单模式。
2. **RAG**：加入可插拔嵌入、版本化索引、SQLite-Vec 检索、阈值、作用域、去重
   和预算。
3. **RAG 增强**：加入记忆与知识库融合、LanceDB 回退报告、重排和记忆树关系。
4. **永久记忆治理**：加入候选状态、白名单、可信确认、规范键冲突和有界提示词
   注入。
5. **实验性写实模式**：所有不变量均有测试后，再加入衰减、调度器、遗忘恢复、
   最终删除和生命周期控制。

## 20. 系统不变量

1. 没有工具调用就没有记忆写入。
2. 对话记录持久化绝不意味着记忆持久化。
3. LLM 提出语义意图，Rust 执行状态和时间规则。
4. 普通消息永远不能成为永久记忆。
5. 重要性和回忆频率永远不能绕过永久记忆资格检查。
6. 永久记忆必须是原子化、有规范键、经过确认并完成冲突检查的事实。
7. 每条记忆只能属于一个组，继承关系不能复制或改变其所属。
8. 角色不能读取未继承的非全局组；未指定目标组的写入只能进入角色默认组，写入
   其他组必须同时具备显式目标和写权限。
9. SQLite 始终是权威数据源，向量库始终可以重建。
10. 写实模式不能通过正常模式升级进入。
11. 遗忘记忆在到期前可以恢复，最终删除必须是确定性的。
12. 所有实质性记忆操作都必须能够归因和审计。
